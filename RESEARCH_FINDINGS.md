# Research Findings: VAE-Augmented Network Intrusion Detection

Source material for writing the research paper. Every number here comes from
the files in `results/`, the pipeline logs from the 2026-09-26 run, or
`data/processed/*/dataset_info.json`. Where a claim is an interpretation
rather than a measurement, it says so.

Code: https://github.com/roipaname/vae-network-intrusion-detection
Trained models and datasets: [v1.0-artifacts release](https://github.com/roipaname/vae-network-intrusion-detection/releases/tag/v1.0-artifacts)

---

## 1. Summary

Intrusion detection systems often train on limited, imbalanced normal
traffic. We tested whether a Variational Autoencoder (VAE), trained only on
real normal traffic, can generate synthetic normal traffic that improves a
detector when added to its training data.

**It did not.** On NSL-KDD and UNSW-NB15, a Random Forest trained on real
data plus 5,000 VAE-generated normal samples performed the same as, or
slightly worse than, the same model trained on real data alone, on every
metric. That includes false positive rate, which augmentation was expected
to reduce.

| Dataset | Accuracy change | F1 change | Recall change | FPR change |
|---|---|---|---|---|
| NSL-KDD | −1.19 pp | −1.58 pp | −2.05 pp | +0.05 pp |
| UNSW-NB15 | −0.14 pp | −0.10 pp | −0.02 pp | +0.28 pp |

*pp = percentage points; the change is augmented minus baseline.*

Three supporting findings explain the result:

1. **Synthetic category columns are realistic; synthetic numeric columns are
   not.** The categorical distributions match well (total variation distance
   0.01–0.09). The numeric distributions match only moderately (mean KS
   statistic 0.57 on NSL-KDD, 0.40 on UNSW-NB15), and the worst matches are
   sparse, nearly constant features.
2. **A standard fix for the VAE's latent-space mismatch made the synthetic
   data slightly worse.** This held on both datasets.
3. **The extra "normal" samples made the detector miss more attacks.** They
   did not reduce false alarms. On NSL-KDD, augmentation added 263 missed
   attacks and 5 false alarms.

Across two runs with identical training, the size of the harm on NSL-KDD
changed by an order of magnitude (−0.10 pp vs −1.19 pp accuracy). The only
difference between the runs was which synthetic samples were drawn. The
direction (no benefit) never changed, but a single run can't fix the
magnitude (see §7.2).

## 2. Research problem and question

**Problem.** Intrusion detectors that learn from labelled traffic depend on
how much normal traffic they see and how varied it is. With limited or
unrepresentative normal data, they produce false positives and generalise
poorly to unseen traffic.

**Research question.**

> Can synthetic normal traffic generated by a Variational Autoencoder improve
> the performance of a network intrusion detection model compared with
> training on real data alone?

**Hypotheses as tested.**

- **H1:** a VAE trained only on real normal traffic can generate synthetic
  normal traffic whose feature distributions match the real data.
- **H2:** adding that synthetic data to the detector's training set improves
  detection metrics on an untouched real test set, especially false positive
  rate.
- **H3 (secondary, arose during the work):** sampling the VAE's latent space
  from a Gaussian fitted to the encoded real data, instead of the standard
  N(0, I) prior, improves the synthetic data's fidelity.

**Outcome.**
- H1 was partially supported: categorical fidelity was good, numeric
  fidelity moderate.
- H2 was not supported.
- H3 was not supported: fidelity got slightly worse.

*The attack family counts for UNSW-NB15 are before duplicates were removed.*

**Why two datasets.** We used NSL-KDD, the classic benchmark, to develop the
method. We then ran UNSW-NB15, which is newer and has a different feature
set, through the identical pipeline to check whether the result generalises.

**Sources.** Neither dataset's official host allows scripted download: the
NSL-KDD host (UNB/CIC) has taken the dataset offline, and UNSW-NB15 is
hosted in a SharePoint folder. We took the files from community mirrors
(`jmnwong/NSL-KDD-Dataset` and `Nir-J/ML-Projects` on GitHub) and accepted
them only after the record counts matched the published figures exactly
(Tavallaee et al., 2009; Moustafa & Slay, 2015). Both datasets' official
train/test splits were used as-is.

**Duplicates in UNSW-NB15.** 38.6% of UNSW-NB15's official training set is
duplicate rows. We dropped duplicates from the training set only and left
the test set untouched. This is worth reporting: many published UNSW-NB15
results don't say whether they deduplicated, and duplicates inflate the
apparent training set size.

## 4. Methodology

### 4.1 Preprocessing

- **Labels.** A binary label (0 = normal, 1 = attack) and an attack family
  for each record.
- **Encoding.** A single `sklearn.ColumnTransformer` one-hot encodes the
  categorical columns and standard-scales the numeric columns. It is fit
  **on the training set only** and then applied to the test set, so no
  information leaks from test to train.
- **Normal subset.** The normal-only part of the training set
  (`X_train_normal`) is split out. It is the only data the VAE ever sees.
  The VAE never sees attack traffic or the test set.

### 4.2 Variational Autoencoder

| Component | Setting |
|---|---|
| Encoder | MLP, input → 64 → 32, ReLU, separate μ and log σ² heads |
| Latent dimension | 16 |
| Sampling during training | Reparameterisation, z = μ + ε·exp(½ log σ²), ε ~ N(0, I) |
| Decoder | Mirror of the encoder with a linear output layer (inputs are standardised, not bounded to [0, 1]) |
| Loss | MSE reconstruction + KL(q(z∣x) ∥ N(0, I)), each per sample then averaged over the batch; KL weight 1.0 |
| Optimiser | Adam, learning rate 1e-3, batch size 128, 50 epochs |
| Seed | 42 (`torch.manual_seed`) |

**Training outcome (epoch 50).**

| Dataset | Total loss | Reconstruction | KL |
|---|---|---|---|
| NSL-KDD | 8.26 | 5.11 | 3.16 |
| UNSW-NB15 | 7.38 | 3.46 | 3.92 |

These losses were reproduced exactly when the pipeline was re-run, so VAE
training is deterministic.

### 4.3 Generating synthetic traffic

We drew 5,000 latent vectors and decoded them into synthetic normal records.
We compared two ways of drawing them:

- **Prior sampling (default):** z ~ N(0, I).
- **Posterior-fit sampling:** z ~ N(m, diag(s²)), where m and s are the mean
  and standard deviation of the encoded μ vectors across all real normal
  training records. This targets a measured mismatch: real data encodes to
  μ with standard deviation ≈ 0.42, much narrower than the prior's 1.0.

The synthetic data is saved separately and never merged with real data on
disk.

### 4.4 Measuring synthetic fidelity

Real normal training data was compared with the 5,000 synthetic samples:

- **Numeric features:** a two-sample Kolmogorov–Smirnov (KS) statistic for
  each feature (0 = identical distributions, 1 = completely separate). We
  report the mean across features.
- **Categorical features:** the decoder outputs a continuous value for every
  one-hot column. For measurement, each synthetic record is assigned the
  category with the highest output value in each group. The resulting
  category frequencies are compared with the real ones using total
  variation (TV) distance.

### 4.5 Detector experiments

| Setting | Value |
|---|---|
| Model | Random Forest, 200 trees, unlimited depth, seed 42 |
| Experiment A (baseline) | Real training data only |
| Experiment B (augmented) | Real training data + 5,000 prior-sampled synthetic records, all labelled normal |
| Evaluation | The same untouched real test set for both. Synthetic data is never added to the test set |
| Metrics | Accuracy, precision, recall, F1, ROC-AUC, false positive rate, confusion matrix, feature importance |

The two experiments differ **only** in the training data; the model
settings are identical. The synthetic samples are 3.8% (NSL-KDD) and 4.4%
(UNSW-NB15) of the augmented training set. They are 6.9% and 8.8% of its
normal class.

**Why a Random Forest.** It is a strong baseline for tabular intrusion data
that needs little tuning. It is insensitive to feature scale. It also
reports feature importances, which we use as a check that the pipeline is
working (§5.4).

## 5. Results

### 5.1 Synthetic data fidelity (H1)

| Dataset | Mean numeric KS | Median numeric KS | Best-matched numeric features (KS) | Worst-matched numeric features (KS) |
|---|---|---|---|---|
| NSL-KDD | 0.570 | 0.551 | `count` 0.28, `dst_host_srv_diff_host_rate` 0.29, `srv_count` 0.30 | `wrong_fragment` 0.83, `num_outbound_cmds` 0.82, `serror_rate` 0.78, `num_failed_logins` 0.78 |
| UNSW-NB15 | 0.401 | 0.441 | `dmean` 0.13, `dtcpb` 0.16, `sbytes` 0.18 | `sinpkt` 0.79, `is_sm_ips_ports` 0.75, `ackdat` 0.62, `rate` 0.58 |

| Dataset | Categorical TV distance by column |
|---|---|
| NSL-KDD | `protocol_type` 0.037 · `service` 0.075 · `flag` 0.038 |
| UNSW-NB15 | `proto` 0.013 · `service` 0.090 · `state` 0.034 |

**Reading.** The categorical distributions match closely. The numeric
distributions are clearly distinguishable from the real ones (every KS
p-value is effectively 0 at these sample sizes).

The worst numeric matches are sparse or nearly constant in the real data.
For example, `wrong_fragment` and `num_outbound_cmds` are almost always one
value, with rare spikes. The VAE has Gaussian-style MSE loss and a linear
output, so it produces a smooth continuous spread around that value instead
of the real near-single-value pattern. Denser, more continuous features
(`count`, `srv_count`, `sbytes`, `dmean`) match much better.

The VAE also compresses variance. For NSL-KDD `duration`, the real standard
deviation is 0.50 but the synthetic one is 0.37. For UNSW-NB15 `dur`, the
real standard deviation is 0.78 but the synthetic one is 0.27.

### 5.2 Latent sampling strategy (H3)

| Dataset | Metric | Prior | Posterior-fit | Change |
|---|---|---|---|---|
| NSL-KDD | Mean numeric KS | 0.570 | 0.604 | worse by 0.034 |
| NSL-KDD | Mean categorical TV | 0.050 | 0.072 | worse by 0.022 |
| UNSW-NB15 | Mean numeric KS | 0.401 | 0.407 | worse by 0.005 |
| UNSW-NB15 | Mean categorical TV | 0.045 | 0.046 | worse by 0.001 |

The latent statistics behind the hypothesis were as follows. The encoded μ
had a standard deviation of 0.424 (NSL-KDD) and 0.416 (UNSW-NB15), with a
mean close to 0. The average per-record encoder σ was 0.88 and 0.86.

**Interpretation (not a measurement).** Fitting one diagonal Gaussian over
all encoded μ vectors merges whatever clusters exist in the latent space,
for example separate regions for different protocols or services. During
training the decoder only ever received z = μᵢ + εσᵢ for a specific real
record i. It never received a draw from this coarse global fit, so those
draws land in regions that don't correspond to any real traffic mode.

The correct aggregate-posterior sampler is a mixture: pick a real record i,
then draw z ~ N(μᵢ, σᵢ²). We didn't test it; it is listed as future work.

### 5.3 Detector performance (H2)

| Dataset | Variant | Accuracy | Precision | Recall | F1 | ROC-AUC | FPR |
|---|---|---|---|---|---|---|---|
| NSL-KDD | Baseline | 77.61% | 96.89% | 62.67% | 76.11% | 0.9619 | 2.66% |
| NSL-KDD | Augmented | 76.42% | 96.73% | 60.62% | 74.54% | 0.9605 | 2.71% |
| UNSW-NB15 | Baseline | 87.20% | 81.86% | 98.60% | 89.46% | 0.9807 | 26.76% |
| UNSW-NB15 | Augmented | 87.06% | 81.70% | 98.58% | 89.35% | 0.9804 | 27.05% |

Precision, recall, F1 and FPR are computed with *attack* as the positive
class.

**Confusion matrices** (TN = normal correctly passed, FP = false alarm,
FN = missed attack, TP = attack caught):

| Dataset | Variant | TN | FP | FN | TP |
|---|---|---|---|---|---|
| NSL-KDD | Baseline | 9,453 | 258 | 4,790 | 8,043 |
| NSL-KDD | Augmented | 9,448 | 263 | 5,053 | 7,780 |
| UNSW-NB15 | Baseline | 27,098 | 9,902 | 633 | 44,699 |
| UNSW-NB15 | Augmented | 26,993 | 10,007 | 643 | 44,689 |

**Reading.**
- **Where the errors moved.** On NSL-KDD, almost all of the change is in
  missed attacks (+263 FN), not false alarms (+5 FP). The added "normal"
  samples didn't reduce false alarms. Instead, they appear to claim parts of
  the feature space where real attacks sit, so some attacks are now
  classified as normal. On UNSW-NB15, the change is small and mostly extra
  false alarms (+105 FP, +10 FN).
- **Baseline behaviour differs by dataset.** On NSL-KDD the baseline is
  precise but misses many attacks (62.7% recall), because KDDTest+ contains
  attack types that are absent from the training set. On UNSW-NB15 it
  catches almost every attack (98.6% recall) but raises false alarms on 26.8%
  of normal traffic. Augmentation was intended to address that kind of
  problem, and it made it slightly worse.

### 5.4 Feature importance (pipeline check)

The top features match those reported in the literature for each dataset.
This suggests the null result reflects a genuine lack of benefit rather than
a broken pipeline.

- **NSL-KDD:** `src_bytes` 0.142, `dst_bytes` 0.112, `flag` 0.086,
  `service` 0.078, `same_srv_rate` 0.054.
- **UNSW-NB15:** `sttl` 0.117, `ct_state_ttl` 0.103, `dload` 0.049,
  `dttl` 0.048, `tcprtt` 0.042.

In the UNSW-NB15 dataset paper, `sttl` and `ct_state_ttl` are the top
predictors (Moustafa & Slay).

## 6. Discussion

**Answer to the research question.** In this setup, VAE-generated normal
traffic did not improve intrusion detection on either dataset. The accurate
claim is "no measurable benefit, with a small cost", not "augmentation is
harmful in general". Effect sizes are at most about 2 pp, and the NSL-KDD
magnitude varies between runs (§7.2).

**A plausible explanation (interpretation).** The results form a consistent
chain:

1. The synthetic numeric features are smoothed and have too little variance
   (§5.1). Synthetic "normal" records therefore sit in a blurred region of
   feature space instead of on the real normal-traffic data.
2. When a Random Forest labels those records normal, the tree splits shift
   to make room for them.
3. On NSL-KDD, some of that region overlaps real attacks, particularly
   test-set attacks that already look like normal traffic. The detector
   therefore misses more attacks (FN +263) without any drop in false alarms.

In short, augmentation only helps if the synthetic data fills real gaps in
the normal class. Here, it adds data to a region that doesn't correspond to
real traffic.

**The one-hot problem (a validity issue and a likely contributor).** The
synthetic records' categorical columns are passed to the detector exactly as
the decoder produced them: continuous values, not clean one-hot vectors.
Fidelity was measured by picking the highest value in each group (§4.4),
but the detector was trained on the raw values. Real records always have
exactly one 1 per group, so synthetic records are separable from real ones
on these columns alone. Snapping each group to a one-hot vector before
augmenting is a cheap fix. It should be the first thing tested before
claiming the null result is fundamental to VAE augmentation.

**Relation to the motivation.** The hoped-for benefit was a lower false
positive rate. Neither dataset showed it. UNSW-NB15's false alarms (26.8%)
appear to come from the gap between its train and test distributions, not a
shortage of normal training data. Its 51,890 real normal records are already
far more than the 5,000 synthetic ones added. Synthetic data drawn from the
same training distribution can't correct a shift between train and test.

**Value of the negative results.** Both null findings are reproducible from
the files in `results/`: detection (H2) and the sampling fix (H3). The H3
result also warns against a common intuition: fitting a single Gaussian to
the encoded training data is not a free improvement over the standard N(0, I)
prior.

## 7. Limitations and threats to validity

### 7.1 Design limitations
- **One detector with fixed settings.** Only a Random Forest was tested, and
  it wasn't tuned. Models that learn smoother decision boundaries, such as
  neural networks, could respond differently to augmentation.
- **One augmentation size.** Only 5,000 samples were added (about 7–9% of
  the normal class). No dose-response curve was measured.
- **One VAE configuration.** The VAE used a 16-dimensional latent space, a
  KL weight of 1.0 and 50 epochs. No sweep was run over β or architecture,
  and no other generators (for example a conditional VAE, a GAN, or a
  diffusion model) were compared.
- **Continuous one-hot outputs.** The synthetic categorical columns reached
  the detector as continuous values, not one-hot vectors (§6).
- **Binary task only.** Per-family detection was not measured separately.
  This matters most for rare attack families (NSL-KDD's U2R has only 52
  training records).

### 7.2 Statistical limitations
- **No repeated trials, and synthetic sampling isn't seeded.** Each
  experiment ran once. VAE training is seeded and deterministic, but the
  generation step draws latent vectors without resetting the seed, so the
  5,000 synthetic samples differ between runs. Across two full runs,
  NSL-KDD's augmented accuracy was 77.51% and then 76.42%, a change of
  −0.10 pp and then −1.19 pp against a baseline that reproduced exactly.
  On UNSW-NB15 the change was −0.16 pp and then −0.14 pp. The direction held
  both times, but **the paper should report the mean ± standard deviation
  over several generation seeds and use a paired significance test** before
  stating any effect size.
- **No confidence intervals** are given for any metric yet.

### 7.3 Dataset limitations
- **Dataset age and realism.** NSL-KDD is derived from 1998 DARPA traffic
  and has well-documented problems with how realistic it is. UNSW-NB15 is
  newer but still generated in a lab.
- **Records are flow summaries.** Each record summarises a whole
  connection; there are no raw packets, IP addresses or timestamps.
  Everything is detected per record, with no time ordering.
- **Mirrored copies.** The datasets came from community mirrors, not the
  official hosts. Record counts matched the published figures, but we didn't
  compare checksums against an official source.
- **Train/test overlap in UNSW-NB15.** Duplicates were removed within the
  training set only. We did not check whether test records also appear in
  the training set.

## 8. Future work

Listed roughly in order of how much each would strengthen the paper:

1. **Seeded repeated trials** (for example 5–10 generation seeds) with mean
   ± standard deviation and a paired test. This is needed to state any
   effect size.
2. **Snap the synthetic categorical columns to one-hot vectors** before
   augmenting, then re-run H2.
3. **A proper aggregate-posterior sampler**: pick a real record, then draw
   from that record's encoder distribution. This is a fair test of whether
   H3 fails because of the idea or because of the single-Gaussian shortcut.
4. **Dose-response**: vary the number of synthetic samples, for example
   1k, 5k, 20k, and 50k, or match it to the real normal count.
5. **Better handling of sparse features**: a mixed-type likelihood (Bernoulli
   or categorical outputs for binary and one-hot columns, zero-inflated
   outputs for sparse counts), or a β-VAE sweep.
6. **Other detectors** (gradient boosting, MLP, one-class and
   anomaly-detection models) and **other generators** (CTGAN, TVAE,
   diffusion models).
7. **Low-data regime.** Deliberately reduce the real normal training set,
   for example to 1%, 5% or 10%, to test the scenario the motivation
   describes, where normal data is scarce.
8. **Per-family metrics**, especially for the rare families (U2R, R2L,
   Worms).

## 9. Reproducibility

- **Environment.** Python 3.11, managed with `uv`. PyTorch is pinned to
  2.2.2 (the last release with Intel-Mac wheels), which requires `numpy<2`
  and `pandas<3`. Pipeline stages ran on CPU.
- **Pipeline.** Run these in order from the repo root (README §15):
  ```bash
  uv run python -m src.data --dataset all
  uv run python -m src.vae --dataset all
  uv run python -m src.evaluation --dataset all --stage synthetic
  uv run python -m src.detector --dataset all
  uv run python -m src.evaluation --dataset all --stage detectors
  ```
- **Artifacts.** The trained models, raw data and processed data from the
  run reported here are in the
  [v1.0-artifacts release](https://github.com/roipaname/vae-network-intrusion-detection/releases/tag/v1.0-artifacts),
  with SHA-256 checksums.
- **Results files** (`results/`):

| File | Contents |
|---|---|
| `*_baseline_metrics.json`, `*_augmented_metrics.json` | All metrics, confusion matrix, classification report, ROC curve points |
| `*_comparison.json` | Baseline vs augmented side by side, deltas, both ROC curves |
| `*_synthetic_validation.json` | Fidelity per feature and per category (prior sampling) |
| `*_synthetic_validation_posterior.json` | The same, for posterior-fit sampling |
| `*_latent_sampling_comparison.json` | H3 comparison and latent statistics |
| `*_feature_importance_{baseline,augmented}.json` | Top features by importance |

- **Suggested figures**, all drawable from the files above:
  1. ROC curves, baseline vs augmented, for each dataset
     (`*_comparison.json`).
  2. KS statistic per numeric feature, sorted, for each dataset.
  3. Real vs synthetic category frequencies for `service` (the worst-matched
     categorical column).
  4. Confusion matrices side by side, showing where the errors moved.
  5. A 2D projection of the latent space: real normal, synthetic and real
     attack records (served by the backend at `/api/latent-projection`).

## 10. Other things built (possible system or demo section)

Alongside the experiments, the project includes a working prototype:

- **FastAPI backend** (`backend/main.py`). It serves real pipeline outputs:
  metrics, feature importances, a 2D projection of real records through the
  trained encoder, and live classification of real test records. The
  datasets have no IP addresses or timestamps, so the display-only fields
  (pseudo-IPs, times) are generated deterministically and labelled as such
  in the code.
- **React dashboard** (`frontend/`). It shows traffic, alerts, model metrics,
  a comparison of the two variants, and the latent-space view.
