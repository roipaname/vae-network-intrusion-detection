# NEXUS AI — VAE-Augmented Network Intrusion Detection

A research prototype investigating whether synthetic normal network traffic,
generated by a Variational Autoencoder (VAE), improves the performance of a
network intrusion detection model compared with training on real data alone.
Includes a full Python ML pipeline, a FastAPI backend, and a React dashboard.

## 1. Research problem

Intrusion detection systems often have limited and imbalanced normal traffic
data, which causes false positives and poor generalization to traffic the
model hasn't seen before.

## 2. Research question

> Can synthetic normal traffic generated by a Variational Autoencoder improve
> the performance of a network intrusion detection model compared with
> training on real data alone?

Both datasets' official hosts are unreachable for scripted download (NSL-KDD's
UNB/CIC host has taken the dataset offline; UNSW-NB15's host is a SharePoint
folder). Files were fetched from long-standing community mirrors and verified
against literature-published record counts before being trusted:

| Dataset | Role | Train | Test | Source |
|---|---|---|---|---|
| **NSL-KDD** | Primary | 125,973 | 22,544 | `jmnwong/NSL-KDD-Dataset` (GitHub) |
| **UNSW-NB15** | Secondary validation | 175,341 | 82,332 | `Nir-J/ML-Projects` (GitHub), standard pre-partitioned train/test split |

**Why NSL-KDD as primary:** smaller, cleaner, faster to iterate on, and the
classic VAE/IDS benchmark. UNSW-NB15 is run through the identical pipeline
afterward to check whether the finding generalizes to a second, more modern
dataset with a different feature set (43 raw features vs. NSL-KDD's 41).

Both datasets ship with an official train/test split, which is used as-is —
no re-splitting, so the two datasets' records are never mixed.

Place the raw files here before running the pipeline:

## 6. Preprocessing

`src/data.py` loads both datasets, assigns the official NSL-KDD column names
(the raw `.txt` files have no header), and derives a binary label (0 = normal,
1 = attack) plus an attack-family category for each dataset.

- Categorical columns (`protocol_type`/`service`/`flag` for NSL-KDD;
  `proto`/`service`/`state` for UNSW-NB15) are one-hot encoded; numeric
  columns are standard-scaled — both fit on the **training set only** via a
  single `sklearn.ColumnTransformer`, then applied to test data, to avoid
  leakage.
- Duplicate rows are dropped from the training set only, never from test.
  NSL-KDD had 0 duplicates; **UNSW-NB15's official training partition had
  67,601 duplicate rows (38%)** — a real, documented quirk of that partition,
  reported honestly rather than hidden.
- The real-normal-only subset of the training data (`X_train_normal`) is
  split out here — this is the only data the VAE ever trains on.

```bash
uv run python -m src.data --dataset all
```

## 7. VAE methodology

`src/vae.py` implements a genuine VAE (not a plain autoencoder):

- **Encoder**: MLP (`122/194 → 64 → 32`) producing `mu` and `logvar` for a
  16-dimensional latent space.
- **Reparameterization trick**: `z = mu + eps * exp(0.5 * logvar)`.
- **Decoder**: MLP mirroring the encoder in reverse, linear output (inputs
  are standard-scaled, not bounded to [0, 1]).
- **Loss**: MSE reconstruction + KL divergence to `N(0, I)`, both computed
  per-sample then averaged over the batch, combined via a configurable
  `KL_WEIGHT`.
- Trained **only** on `X_train_normal` — the VAE never sees attack traffic.

All hyperparameters are centralized in `config/settings.py`
(`LATENT_DIM`, `HIDDEN_DIMS`, `VAE_LEARNING_RATE`, `VAE_BATCH_SIZE`,
`VAE_EPOCHS`, `KL_WEIGHT`, `SYNTHETIC_SAMPLE_COUNT`).

```bash
uv run python -m src.vae --dataset all
```

Results (50 epochs): NSL-KDD final loss 8.26 (recon 5.11, KL 3.16) on 67,343
normal samples; UNSW-NB15 final loss 7.38 (recon 3.46, KL 3.92) on 51,890
normal samples.

## 8. Synthetic traffic generation & validation

`generate_synthetic()` samples `z` from the latent space and decodes it into
synthetic normal traffic, saved separately from real data
(`data/processed/<dataset>/synthetic_normal.npz`) — never merged with real
data on disk.

**Two sampling strategies were tried and measured, not assumed:**

1. `sampling="prior"` — the textbook approach, `z ~ N(0, I)`.
2. `sampling="posterior"` — `z` sampled from a Gaussian fitted to the real
   data's encoded `mu` (motivated by Phase 4's finding that real normal
   traffic's encoded `mu` has std ≈0.42, narrower than the prior's 1.0).

**Finding: the "fix" made fidelity slightly worse, on both datasets**
(`results/*_latent_sampling_comparison.json` has the full write-up and a
candidate explanation — briefly, the single global Gaussian used for
posterior sampling collapses latent cluster structure that per-sample
reparameterization during training never asked the decoder to handle).
`prior` sampling is therefore the default used for detector augmentation.

Validation (`src/evaluation.py`, comparing real vs. synthetic normal traffic):

- **Categorical fidelity is good**: total variation distance 0.02–0.08 across
  protocol/service/flag distributions.
- **Numeric fidelity is mixed and mechanically explainable**: mean KS
  statistic 0.57 (NSL-KDD) / 0.40 (UNSW-NB15) — driven mostly by sparse,
  near-constant features (e.g. `wrong_fragment`) where the VAE reconstructs a
  smoothed continuous approximation instead of the near-degenerate real
  pattern; genuinely continuous features (`count`, `logged_in`) fare much
  better (KS 0.28–0.43).

```bash
uv run python -m src.evaluation --dataset all --stage synthetic
```

## 9 & 10. Baseline and VAE-augmented detector experiments

`src/detector.py` uses a **Random Forest** (200 trees, unconstrained depth,
fixed random seed) — chosen because it's a strong, fast, low-tuning-effort
baseline for tabular IDS data, needs no extra feature-scale handling, and
exposes feature importances directly for the dashboard's explanation panel.

- **Experiment A (baseline)**: trained on real training data only.
- **Experiment B (augmented)**: trained on real training data + 5,000
  VAE-generated synthetic normal samples (prior-sampled), all labeled
  `normal`.

Both experiments use identical hyperparameters; only the training data
differs, and both are evaluated against the **same untouched real test set**
(synthetic data is never added to test data).

```bash
uv run python -m src.detector --dataset all
```

## 11. Evaluation

```bash
uv run python -m src.evaluation --dataset all --stage detectors
```

Computes accuracy, precision, recall, F1, ROC-AUC, false positive rate,
confusion matrix, and feature importance for both variants, saved to
`results/`.

**Results:**

| Dataset | Variant | Accuracy | Precision | Recall | F1 | ROC-AUC | FPR |
|---|---|---|---|---|---|---|---|
| NSL-KDD | Baseline | 77.61% | 96.89% | 62.67% | 76.11% | 0.9619 | 2.66% |
| NSL-KDD | Augmented | 76.42% | 96.73% | 60.62% | 74.54% | 0.9605 | 2.71% |
| UNSW-NB15 | Baseline | 87.20% | 81.86% | 98.60% | 89.46% | 0.9807 | 26.76% |
| UNSW-NB15 | Augmented | 87.06% | 81.70% | 98.58% | 89.35% | 0.9804 | 27.05% |

**Honest conclusion:** VAE-based synthetic normal traffic augmentation, as
implemented here, **did not improve intrusion detection performance on
either dataset**. Every metric moved slightly negative or stayed flat with
augmentation, including false positive rate — one of the paper's specific
hoped-for benefits — which got marginally *worse*, not better. Effect sizes
are small (at most ~2 percentage points, on NSL-KDD recall; under 1 point
everywhere on UNSW-NB15), so the precise claim is "no
measurable benefit," not "actively harmful." This is consistent with the
synthetic data's moderate numeric fidelity (§8) — a plausible causal chain
for the paper's discussion section. Feature importances are domain-sensible
and match published literature for both datasets (NSL-KDD: `src_bytes`,
`dst_bytes`, `flag`, `service`; UNSW-NB15: `sttl`, `ct_state_ttl` — both
well-known top predictors in the respective papers), which gives confidence
the pipeline is functioning correctly rather than coincidentally producing a
null result.

## 12. Backend

FastAPI app in `backend/main.py`. Every endpoint reads a real pipeline
artifact or runs a real preprocessed record through a real trained detector —
nothing is hardcoded. NSL-KDD/UNSW-NB15 have no real IP addresses or
timestamps, so the traffic/alerts/connections/simulation endpoints synthesize
a stable, deterministic display-only value for those fields, clearly
separated in the code from genuine model output and dataset fields.

```bash
uv run uvicorn backend.main:app --reload --port 8000
```

Key endpoints: `/api/summary`, `/api/metrics`, `/api/traffic`, `/api/alerts`,
`/api/feature-importance`, `/api/connections`, `/api/latent-projection`,
`/api/datasets`, `/api/model/{dataset}`, `POST /api/predict`,
`POST /api/simulate-attack`. Full list and docs at `/docs` once running.

## 13. Frontend

React + Vite dashboard in `frontend/`, using the logo's own visual language
(shield = security, split brain/server = AI + infrastructure, mint flow lines
= healthy traffic) and the specified color palette (warm off-white + charcoal
+ white cards + mint accents + amber/coral status colors — no neon, no
gradients). `lucide-react` for icons (no emoji), `recharts` for charts, a
hand-built SVG flow diagram for live traffic, Inter + JetBrains Mono
(installed as npm packages, not a CDN, for offline reliability).

Pages: Overview, Live Traffic, Detection, Simulation, AI Model, Performance,
History, and a Dataset page for each of NSL-KDD/UNSW-NB15.

```bash
cd frontend && npm run dev
```

## 15. How to reproduce the experiments

Run in this order from the project root:

```bash
uv run python -m src.data --dataset all        # download must already be in data/raw/, see §4
uv run python -m src.vae --dataset all          # trains VAE, generates synthetic data (both sampling strategies)
uv run python -m src.evaluation --dataset all --stage synthetic   # validates synthetic data against real
uv run python -m src.detector --dataset all     # trains baseline + augmented Random Forest detectors
uv run python -m src.evaluation --dataset all --stage detectors   # computes all metrics + comparisons
```

Every step is deterministic given `RANDOM_SEED` in `config/settings.py`
(default `42`) and logs its progress via Loguru to stderr and
`logs/app.log`. Raw datasets must be placed under `data/raw/nsl_kdd/` and
`data/raw/unsw_nb15/` first (see §4 for exact filenames and sources) — they
are not committed to the repository.
